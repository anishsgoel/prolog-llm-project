# The London Underground abduction benchmark

A family of abductive knowledge-base-completion problems built on the real
London Underground network: 270 stations, 306 physical adjacencies, five
difficulty tiers.

Each problem takes a complete Prolog KB of `connected/2` facts plus the two
`reachable/2` rules, deletes a few ground facts, and poses a `reachable/2` goal
that is no longer provable. The LLM-guided DFS meta-solver has to hypothesise
the missing adjacencies to recover a proof.

Everything here is generated by [`tools/build_london_benchmark.py`](../tools/build_london_benchmark.py)
from one readable data file, [`tools/london_network.yaml`](../tools/london_network.yaml).
The generator is deterministic: same YAML in, byte-identical KBs and configs out.

```bash
python tools/build_london_benchmark.py verify
```
```bash
python tools/build_london_benchmark.py build --gt-timeout 300
```

---

## 1. Why the data has to be exactly right

The model under test knows the real tube map. That cuts both ways:

* If the KB contains a **wrong or missing** edge, the model proposes the *real*
  edge and the metrics score a correct answer as a hallucination.
* If the KB contains a **shortcut** edge — one joining two stations that have
  another station physically between them — then the shortcut failure mode this
  project studies is baked into the ground truth instead of being measured.

So the benchmark represents **physical adjacency only**, and the data is
verified against two independent sources before anything is generated.

### The structural guarantee against shortcuts

`london_network.yaml` stores each line as ordered **branch sequences**, and an
edge exists only between *consecutive* stations within a sequence. You cannot
write down a long-hop edge without also writing down the stations it skips.
That is the whole reason the data is shaped this way rather than as an edge
list.

### Express skips

Five places on the network run non-stop past stations another line serves. The
long hop must not become an edge; the other line's sequence already supplies
that corridor. These are declared in `express_skips:` and the builder both
suppresses them and asserts they are absent from the final edge set:

| Line | Non-stop segment | Physically between | Supplied by |
|---|---|---|---|
| Metropolitan | Baker Street → Finchley Road | St John's Wood, Swiss Cottage | Jubilee |
| Metropolitan | Finchley Road → Wembley Park | West Hampstead, Kilburn, Willesden Green, Dollis Hill, Neasden | Jubilee |
| Piccadilly | Earl's Court → Barons Court | West Kensington | District |
| Piccadilly | Hammersmith → Turnham Green | Ravenscourt Park, Stamford Brook | District |
| Piccadilly | Turnham Green → Acton Town | Chiswick Park | District |
| Piccadilly | Acton Town → Hammersmith | Chiswick Park, Turnham Green, Stamford Brook, Ravenscourt Park | District |

The last row was **added during verification** — see §2.

A generic detector also runs: for every edge `(u, w)`, if the graph minus that
edge still has a `u–w` path of length 2–3 whose intermediate stations lie on a
line serving both endpoints, the edge is flagged for manual review. It is never
auto-deleted, because the tube really does contain short parallel structures.
All nine current hits belong to three declared `known_parallel_structures`:

* **Camden Town – Euston** (Northern). The Bank-branch tunnels run direct;
  Mornington Crescent is on the Charing Cross branch only.
* **Gloucester Road – High Street Kensington** (the Cromwell Curve). Circle and
  District Edgware Road trains bypass Earl's Court on separate tracks.
* **Hatton Cross – Heathrow Terminals 2 & 3**. The original 1977 tunnel, still
  used by all Terminal 5 trains, alongside the one-way Terminal 4 loop.

## 2. Data verification, and the corrections it produced

Sources: the Wikipedia *List of London Underground stations* table (272 rows)
for station membership and fare zones, the per-line articles for branch order,
and an independent adjacency edge list pulled from **Wikidata** (property P197
*adjacent station*, qualified by P81 *connecting line*), checked in as
[`tools/london_reference_edges.csv`](../tools/london_reference_edges.csv) so the
diff is reproducible offline.

Per-line station counts match the Wikipedia table exactly for all 11 lines:
Bakerloo 25, Central 49, Circle 35, District 60, H&C 29, Jubilee 27,
Metropolitan 34, Northern 52, Piccadilly 53, Victoria 16, Waterloo & City 2.

### Corrections made to the draft data

1. **Express-skip `between` list was in reverse order.** The Metropolitan's
   Baker Street → Finchley Road skip was given as `[Swiss Cottage, St John's Wood]`.
   Travelling from Baker Street the order is `[St John's Wood, Swiss Cottage]`.
   Caught by the assertion that the skipped corridor exists as an unbroken chain.
2. **A sixth express skip was missing.** Wikidata carries a Piccadilly
   `Acton Town – Hammersmith` adjacency, which is the daytime non-stop pattern
   (Turnham Green has Piccadilly service only early morning and late evening).
   It is the longest express skip on the network and is now declared.
3. **`lamberth_north` → `lambeth_north`** in `london_directed.pl` and
   `london_undirected.pl` (R6). No config referenced the atom.

### Deliberate deviations from the 272-station figure

Wikipedia's 272 rows split **three** stations that this benchmark treats
differently:

| Station | Wikipedia | Here | Why |
|---|---|---|---|
| Edgware Road | 2 rows | **2 stations** | Opposite sides of Marylebone Road, no shared track; the tube map draws two separate dots. Merging them would invent an interchange. |
| Hammersmith | 2 rows | **1 station** | Two buildings, but the tube map draws one interchange dot and a model asked about "Hammersmith" means the interchange. |
| Paddington | 2 rows | **1 station** | Praed St and Bishop's Bridge Rd platform pairs, one station to any passenger. |

Hence **270 stations**, not 272. Splitting Hammersmith or Paddington would
require atoms like `hammersmith_district_piccadilly` that no model would ever
propose, which would manufacture hallucinations (R1).

### Residual diff against Wikidata, fully accounted for

*In Wikidata, not here (13):* six express skips (correctly excluded); Aldwych ×2
and Epping–North Weald (closed 1994); `Edgware Road – Marylebone` (Wikidata does
not split Edgware Road; we emit `Edgware Road (Bakerloo) – Marylebone`);
`Latimer Road – Shepherd's Bush Market` (**Wikidata is stale** — Wood Lane opened
between them in 2008); and two Wikidata data errors where a Kazan Metro and a
Bangkok adjacency carry a London line qualifier.

*Here, not in Wikidata (4):* `Kennington – Nine Elms` and
`Nine Elms – Battersea Power Station` (Wikidata is missing the 2021 Battersea
extension), plus the two `Edgware Road (Bakerloo)` edges from the deliberate split.

Nothing is unexplained.

### Closed and unbuilt stations

Absent, and asserted absent: Aldwych, Brompton Road, Down Street, York Road,
Wood Lane (Central, closed 1947 — the *operational* Circle/H&C Wood Lane is
included and is a different station), British Museum, Ongar, North Weald, Blake
Hall, Cassiobridge, Watford Vicarage Road, and the unbuilt Bakerloo extension to
Lewisham.

## 3. Canonical atoms

`parse_predicate` accepts only `[a-z_][a-zA-Z0-9_]*` functors, and `is_variable`
treats an argument starting with an uppercase letter **or an underscore** as a
variable. So every station atom starts with a lowercase letter and contains only
`[a-z0-9_]`.

Rule: lowercase → `&` becomes `and` → drop apostrophes (including U+2019) and
periods → every other non-alphanumeric run becomes one `_` → collapse repeats →
strip leading/trailing `_`.

| Official name | Atom |
|---|---|
| King's Cross St Pancras | `kings_cross_st_pancras` |
| St James's Park | `st_jamess_park` |
| Elephant & Castle | `elephant_and_castle` |
| Heathrow Terminals 2 & 3 | `heathrow_terminals_2_and_3` |
| Harrow-on-the-Hill | `harrow_on_the_hill` |
| Kensington (Olympia) | `kensington_olympia` |
| Edgware Road (Bakerloo) | `edgware_road_bakerloo` |

The complete mapping is emitted as [`station_atoms.csv`](../station_atoms.csv).
The builder asserts no two stations collide onto one atom.

## 4. KB format

```prolog
1. connected(baker_street, marylebone).  # connected/2 = ADJACENT STOPS ONLY. …
2. connected(marylebone, baker_street).
…
49. reachable(X, Y) :- connected(X, Y).  # reachable/2 = PATH EXISTS. …
50. reachable(X, Z) :- connected(X, Y), reachable(Y, Z).  # …transitive closure…
```

* Every physical edge is **two explicit facts**, emitted as adjacent,
  consecutively numbered lines (`2k-1`, `2k`). Metrics match facts by exact atom
  string, so without both directions a model proposing the reverse edge would be
  scored as hallucinating. **Omitting an edge therefore means omitting two fact
  IDs.**
* The two `reachable/2` rules come **last**, after every fact.
* There is deliberately **no symmetry rule**. `connected(X, Y) :- connected(Y, X).`
  (present in the old `london_large.pl` and `london_undirected.pl`) makes proving
  `connected(a,b)` recurse through `connected(b,a)` and back, bounded only by the
  depth limit — almost certainly why `groundtruth.py` warns that symmetric KBs
  take very long.
* `program_parsing` keys predicate comments by functor/arity and the **last**
  commented clause wins, so the recursive rule's comment is the one prompts
  actually show. It therefore restates the base case too.

Each KB has a sidecar `*.edges.json` mapping every edge to its two fact IDs, its
official station names and its lines, so config generation and analysis never
re-derive it.

## 5. Tier ladder

Every tier is an **induced subgraph** of the full network — same atoms, same
edges restricted to the included stations — so results are comparable across
tiers. All five are connected; nothing is stranded by the cuts.

| Tier | KB | Scope | Stations | Edges | Facts |
|---|---|---|---|---|---|
| T1 | `london_t1_bakerloo.pl` | Bakerloo only | 25 | 24 | 48 |
| T2 | `london_t2_zone1.pl` | Inner Circle + Central trunk + Victoria + Northern central | 72 | 86 | 172 |
| T3 | `london_t3_west.pl` | District + Piccadilly + Circle's Hammersmith branch | 112 | 116 | 232 |
| T4 | `london_t4_core.pl` | All 11 lines, Zones 1–3 | 176 | 209 | 418 |
| T5 | `london_t5_full.pl` | Complete network | 270 | 306 | 612 |

Graph shape: 21 degree-1 stations (termini, excluded from omission candidates),
198 degree-2, and a long tail of junctions topped by King's Cross St Pancras
(7), then Baker Street, Green Park, Oxford Circus and Waterloo (6 each).

## 6. Validity gates

A config is emitted only if **all five** pass. The manifest records which
failed for everything rejected.

1. **Provable on the complete tier KB** within the ground-truth budget.
2. **Not provable on the ablated KB** — the omissions are genuinely
   load-bearing. Because every edge is emitted in both directions and an
   omission always drops both, directed Prolog reachability coincides with
   undirected connectivity, so this is checked exactly (and cheaply) as a
   graph cut before any solver runs.
3. **Every station still appears** in the ablated KB (R3). With
   `allow_new_constants: false` a station whose last edge is omitted vanishes
   from the program and the model is then forbidden from naming it.
4. **No omitted edge was the last edge of a degree-1 station** (R3).
5. **Ground truth completes inside the budget**; the measured time is recorded.

Gate 3 has a consequence worth knowing: on a corridor like the Bakerloo, two
*consecutive* omitted edges always strip the station between them of its last
edge. So on-path omissions are **non-adjacent** edges of the shortest path. They
still force a chain of k separate hypotheses, which is the point.

## 7. The ground-truth tractability wall

**This is the most important caveat in the benchmark.**

`Solver` cost grows steeply with the *hop count of the goal*, not just with KB
size. Measured on the generated tiers (nodes pushed / wall-clock, at the minimum
sufficient depth):

| hops | T1 (48 facts) | T2 (172 facts) | T5 (612 facts) |
|---|---|---|---|
| 2 | 63 / 0.02 s | 190 / 0.30 s | 633 / 0.21 s |
| 3 | 351 / 0.21 s | 1 628 / 3.6 s | 6 343 / 17.7 s |
| 4 | 4 012 / 3.8 s | 36 235 / 49 s | 400 218 / 490 s |
| 5 | 15 360 / 18 s | 164 559 / 360 s | — |
| 6 | 51 537 / 111 s | — | — |

Roughly ×5–10 per additional hop. Against the 300 s
`GROUND_TRUTH_TIMEOUT_S` this puts the usable envelope at about **≤5 hops on
T1, ≤4 on T2–T4, ≤3 on T5**.

Two consequences for the design in the original spec:

* The **"medium" (6–10 hops) and "long" (>10 hops) depth bands are not
  reachable** with the current solver, on any tier — including the 25-station
  T1. Raising the timeout does not rescue them; 10 hops extrapolates to hours.
* Since the meta-solver must search the *ablated* KB, which is strictly harder,
  such configs would also time out at run time. Shipping them would produce runs
  whose ground-truth metrics are all `NA`.

The generator therefore **discovers the wall per tier at build time**: goals are
attempted shortest-first, and the first ground-truth timeout marks the tier's
wall, after which longer goals are skipped and recorded in the manifest as
`gate5: skipped, tier hit the ground-truth tractability wall at N hops`. If the
solver is later made faster, re-running the build automatically extends the
envelope with no change to the data or the tier definitions.

**Difficulty therefore varies by tier size (distractor count) rather than by
proof depth.** A 4-hop goal on T5 is searched against 270 stations and 612 facts;
the same goal shape on T1 sees 25 and 48.

### Why it blows up, and what would fix it

`Solver` already memoises on `GoalNode.signature()`. The blowup is not repeated
states but genuinely distinct ones: `unify_soft_kb` and `unify_soft_rules` are
both applied to every open formula, so the search explores every **interleaving**
of "expand `reachable` by rule 2" and "bind the next `connected` atom to a
fact". Each interleaving is a different signature, and the number of them grows
combinatorially with depth.

Memoisation alone will not collapse that. The fix is a **leftmost-atom selection
rule** — standard SLD resolution — so that only the first unresolved atom is
ever expanded. That would make the branching factor the graph degree (~2.3 here)
instead of the number of interleavings. This is noted, not implemented: it
changes proof search semantics for every existing experiment.

## 8. Prompt size

`_prompt_context` used to pass **every** hard fact into **every** LLM call. At
T5 that is 612 fact lines per call — slow, expensive, and over the context
window of a local model.

`solve.llm_search_guidance_policy.select_hard_facts` now selects a
**goal-relevant subgraph**: constants are nodes, two constants are adjacent when
they co-occur in a hard fact, and only facts whose constants all lie within
`hard_prompt_fact_hops` (default 3) of a constant in the goal or in the currently
open subgoals survive. If that is still over `hard_prompt_fact_limit`
(default 400), the nearest facts are kept.

* A KB **at or under the limit is passed through untouched**, so every
  pre-existing config produces byte-identical prompts and old results stay
  reproducible. Only T4 and T5 are affected.
* Truncation is **never silent** — the count included, the count withheld, the
  radius and the seed constants are logged.

## 9. Running it

The tier configs follow the pattern `london_t<N>_<k>edge_<placement>_<NN>`, and
`batch_run.py --configs` accepts shell-style patterns:

```bash
python src/experiment/batch_run.py --configs 'london_t2_*' --runs 3 --output results/london_t2.csv
```
```bash
python src/experiment/batch_run.py --configs 'london_t1_*' 'london_t2_*' --method llm_oneshot
```
```bash
python src/experiment/batch_run.py --list-configs
```

A pattern matching nothing is an error rather than a silently empty run. An
exact stem with no metacharacter is passed through unchanged, so existing
invocations behave exactly as before.

On the cluster the tiers have their own suite, kept separate from the baseline
suite because they are a different workload — 76 configs on much larger KBs,
with their own tractability limits:

```bash
bash scripts/submit_london.sh
```

`scripts/submit_baselines.sh` excludes `london_t*` (via `--exclude-configs`), so
the two suites partition the config set exactly and neither needs updating when
the benchmark is regenerated. Both share `scripts/submit_common.sh`.

When the arrays finish, the dependent compare job writes both
`comparison.md` (per method) and `summary.md` (**per model, per tier, and per
difficulty axis** — omitted-edge count, placement, hops, shortcut plausibility,
junction crossing — plus a reliability table with the ground-truth-`NA` rate).
The tier and difficulty columns come from `benchmark_manifest.csv`, joined on
`config_name`. To regenerate by hand:

```bash
python scripts/summarize_results.py --indir results/london --outdir results/london
```

Report `valid_success`, `proof_matches_gt`, `precision_hypothesized`,
`recall_omitted` and `hallucination_rate`. **Never** report plain `success` as
the headline: the solver can always inject a fact to force a proof, so `success`
is uninformative by construction.

## 10. Known caveats

* **270 stations, not 272** — see §2. Deliberate and documented.
* **Heathrow Terminal 4** is served by a one-way loop in reality. It is modelled
  as undirected edges, alongside the direct Hatton Cross – T2&3 tunnel.
* **The Circle line passes Paddington twice** (two platform pairs). Both map to
  the single `paddington` atom, so the spiral closes into a cycle through it.
* **Depth bands are capped by §7.** Configs cluster at 3–5 hops; the manifest's
  `depth_band` column will show almost entirely `short`.
* **`k = 5` omissions need a long path** (≥9 hops for non-adjacent on-path
  edges), which is past the tractability wall. Expect few or no 5-edge on-path
  configs; the spread placement reaches higher `k` at shorter path lengths.
* The Wikidata reference file is a **snapshot** (retrieved 2026-08-18) and
  contains third-party errors, listed in §2. It is a cross-check, not a source
  of truth.
